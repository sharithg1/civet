# Releasing Civet

A release is a `vX.Y.Z` tag on `main`. Pushing the tag runs
`.github/workflows/release.yml`, which publishes a GitHub Release with:

| Asset | What |
|---|---|
| `Civet_X.Y.Z_macos-aarch64.dmg`, `…_macos-aarch64.app.zip` | Desktop app for Apple Silicon |
| `Civet_X.Y.Z_macos-x86_64.dmg`, `…_macos-x86_64.app.zip` | Desktop app for Intel Macs |
| `civetd-x86_64-unknown-linux-musl`, `civetd-aarch64-unknown-linux-musl` | Static daemons for Linux hosts |
| `civetd-aarch64-apple-darwin`, `civetd-x86_64-apple-darwin` | Daemons for macOS hosts |
| `SHA256SUMS` | SHA-256 of every asset (`shasum -a 256 -c SHA256SUMS --ignore-missing`) |

Release notes are generated by GitHub from the merged PRs and commits since
the previous tag; edit them on the release page afterwards if needed.

## Cutting a release

On an up-to-date, clean `main` with green CI:

```sh
scripts/release.sh 0.1.5 --dry-run   # show what changes, touch nothing
scripts/release.sh 0.1.5             # bump, commit "Release v0.1.5", tag v0.1.5
git push --atomic origin main v0.1.5 # the script prints this; it never pushes
```

`scripts/release.sh` sets the version in the root `Cargo.toml`
(`[workspace.package]`, inherited by every crate including `civetd`) and in
`crates/civet-desktop/tauri.conf.json`, refreshes `Cargo.lock`, commits and
creates an annotated tag. It refuses a dirty tree, a branch other than
`main` (unless `--allow-branch`), an existing tag, or a `main` behind
`origin/main`. To undo before pushing: `git tag -d v0.1.5 && git reset --hard HEAD~1`.
(`crates/civet-desktop/ui/package.json` has its own unused `0.1.0`; it is not
part of the release version.)

The workflow then:

1. **version**: `scripts/check-version.sh vX.Y.Z` fails the run unless the
   tag, `Cargo.toml` and `tauri.conf.json` all say `X.Y.Z`.
2. **daemons** (macOS runner): builds all four `civetd` binaries with
   `scripts/build-remote.sh` (`dist` profile; Linux via `cargo-zigbuild`) and
   checks each one's embedded version marker.
3. **app** (aarch64 and x86_64, both cross-built on an Apple Silicon runner):
   copies the two Linux daemons and the matching Mac daemon from step 2 into
   `crates/civet-desktop/civet-dist`, then `CIVET_SKIP_DAEMONS=1 pnpm tauri
   build --target <triple> --bundles app,dmg`. Because the bundled daemons are
   the files from step 2, they are the release version: the app refuses a
   `civetd` from another version ("is civetd 0.1.3, expected 0.1.4"). The job
   checks the bundled daemons' versions, `Info.plist` and the signature.
4. **publish**: writes `SHA256SUMS` and runs `gh release create --generate-notes`.
   Tags with a suffix (`v0.2.0-rc.1`) become pre-releases. Re-running a
   failed run replaces the assets of an existing release.

Pull requests that change `release.yml`, `scripts/build-remote.sh`,
`scripts/check-version.sh` or `tauri.conf.json`, and manual runs (Actions →
Release → Run workflow), do steps 1–3 without publishing; the app and daemon
builds are kept as workflow artifacts.

If the tag check fails (tagged the wrong commit, forgot the bump): delete the
tag locally and on GitHub (`git push origin :refs/tags/vX.Y.Z`), fix, and
tag again.

## Signing and notarization

Without secrets the app gets an ad-hoc signature (`APPLE_SIGNING_IDENTITY=-`):
the bundle is sealed but not from an identified developer, so macOS blocks
the downloaded app ("cannot be opened" / "is damaged"). Users clear the
quarantine flag once after installing:

```sh
xattr -dr com.apple.quarantine /Applications/Civet.app
```

(or right-click → Open, or System Settings → Privacy & Security → Open
Anyway, depending on the macOS version). The standalone `civetd` downloads
are not affected when fetched with `curl`/`wget`; if downloaded with a
browser, run `xattr -d com.apple.quarantine civetd-*-apple-darwin`.

Signing and notarization turn on by themselves when these repository secrets
exist (Settings → Secrets and variables → Actions):

| Secret | Value |
|---|---|
| `APPLE_CERTIFICATE` | base64 of the "Developer ID Application" certificate + key exported as `.p12` (`base64 -i cert.p12 \| pbcopy`) |
| `APPLE_CERTIFICATE_PASSWORD` | the `.p12` export password |
| `APPLE_SIGNING_IDENTITY` | e.g. `Developer ID Application: Your Name (TEAMID)` |
| `APPLE_ID` | Apple ID email used for notarization |
| `APPLE_PASSWORD` | an app-specific password for that Apple ID |
| `APPLE_TEAM_ID` | the 10-character team ID |

With the first three the app (and the Mac daemons, with the hardened runtime
and a timestamp) are signed; with all six Tauri also notarizes and staples
the app. The run summary says which mode was used. The signed path has not
been exercised yet: check the first signed release with
`spctl -a -vv /Applications/Civet.app` and
`codesign -dv --verbose=4 /Applications/Civet.app`.

## Building release artifacts locally

```sh
cd crates/civet-desktop/ui && pnpm install
pnpm tauri build --bundles app,dmg                              # this Mac's arch
pnpm tauri build --target x86_64-apple-darwin --bundles app,dmg # Intel (rustup target add x86_64-apple-darwin)
```

`beforeBuildCommand` runs `scripts/build-remote.sh --bundle`, which builds the
Linux daemons and the daemon for the target Mac (from Tauri's
`TAURI_ENV_TARGET_TRIPLE`). Output is under `target/release/bundle/`
(`target/<triple>/release/bundle/` with `--target`).
